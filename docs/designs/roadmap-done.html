1. Desktop roadmap: a fourth column, Done

Ana (owner) has just marked Website done. It sits at the top of Done with today's date. The column shows the newest 5 of 14, then "Show all 14". Done cards keep their name, colour, owner and summary, but drop the shadow, the pencil and the progress bar.

Desktop · 1440 · owner, 14 done projects, toast after marking Website done

Decisions

  1. Four equal columns. At 1440 each is about 270px wide, the same card layout as today, one card per row.
  2. Done comes last, after Later, reading left to right like the board's To do to Done.
  3. The hint under the title says what the column is: "Finished projects, newest first".
  4. "Show all 14" is a link under the 5th card, like "All done tasks" on the board. It reloads the lane with every done project; the link then reads "Show newest 5".
  5. Toast copy from the brief: "Website done. 4 tasks closed."

The done card

  1. Badge "Done 25 Oct" with a green tick, outlined and fully rounded. The free-text status pill is grey with square-ish corners, so the two never look alike.
  2. The free-text status ("Active") is hidden on done cards. "Active" on a finished project would only confuse.
  3. The progress bar goes. It would always read 100%, and the badge says it better.
  4. The colour strip fades to 40% so the column reads as calm. All text stays at full contrast; nothing is dimmed with opacity.
  5. "By Ana" (who marked it done; full wording in the tooltip and screen-reader text) sits in the footer, with Reopen beside it for owners, admins and the project's owner. Reopen is a quiet text button in the link colour, not an outlined button: it repeats on every card in the column, and the longer "Marked done by Maya" wrapped onto two lines at 270px.

2. Phone: the lane switcher with four segments

It fits at 390px with no change to the control. The switcher is 358px wide, so each segment is 84px. The longest likely label, "Later 12", is about 62px at 14px semibold. The count moves into its own muted span so the four words stay easy to scan. Below 360px (iPhone SE first generation, or large text) the count drops under the word, and each segment grows to 44px tall.

Why not something else

  • A scrolling chip row would hide Done off the right edge, the one lane people will look for.
  • Dropping counts loses "how many in Now", which people use today.
  • A "Done" link under the cards would make Done feel like a different page from the lanes.

Markup change: {{ l.label }}<span class="seg-count">{{ l.count }}</span>, plus one media query for under 360px.

3. Marking a project done

There is no project page today. Tapping the pencil opens the edit sheet, and that is where people manage a project, so "Mark project done" lives there, as the brief says. It sits in its own box above the buttons, apart from Save and Delete. Tapping it swaps the sheet to a confirm step. It does not stack a second sheet.

"Who gets a notice" names the assignees and the project owner, without the person closing. With 5 or more names: "Maya, Tom and 3 others get a notice."

Decisions

  1. The box line tells you before you tap: "Its 4 open tasks are marked done with it."
  2. Confirm is a step in the same sheet. Back returns to the form with nothing lost.
  3. The confirm button is the amber primary, "Mark done". It is not red: the action can be undone.
  4. While saving, both buttons are disabled and the primary shows a spinner with "Marking done…".
  5. On error the sheet stays open with a coral alert: "Couldn't mark Website done. Nothing was changed. Try again." The button comes back.
  6. On success the sheet closes, the lane reloads (roadmap-changed) and the toast shows. On a phone the switcher stays on Now. Website has left it, and "Done 14" counts up.

4. A done project

The done card is the closed project's whole view. It has no project page and no edit sheet. It shows the closed state, who marked it done, when, and how many tasks. Owners, admins and the project's owner get Reopen. Everyone else sees the same card without it.

Done card states at phone width

Decisions

  1. Reopen is one tap, with no confirm. It is the undo for a mistake, and marking done again is always possible.
  2. While reopening, the button shows a spinner and "Reopening…".
  3. After it: the card leaves Done and goes back to its old lane. Toast: "Website is back in Now. 3 tasks reopened." The count is the tasks that went back to an earlier status.
  4. If someone set a task back to in progress after the close, the card shows a blue "1 open task" pill. The project stays done.
  5. "12 tasks done" is plain text, not a link. The tasks still show in Tasks with the Done filter.
  6. Dates: "25 Oct" this year, "12 Dec 2025" for earlier years.

5. Home: a donut at the top of "Roadmap: now"

One donut for the whole organisation: the 50 tasks in the three "now" projects, by status. Done 31, in progress 9, blocked 3, to do 7, so the centre reads 62%. It sits in a card above the project cards, 120px, with the legend beside it. It is drawn on the server as plain SVG circles, using the status colours.

Phone · 390 · Home
States at phone width

Decisions

  1. The order goes clockwise from 12 o'clock: done, in progress, blocked, to do. That is how close the work is to finished, and the legend follows the same order.
  2. Status colours from the tokens, so the light and dark versions are each set by design. Each colour stands out against the card at 3:1 or more (light: done 3.4, in progress 4.6, blocked 4.1, to do 3.6; dark: 6.3 to 7.4).
  3. Neighbouring colours are too close to each other, so a 2px gap in the card colour separates every segment. Colour never works alone: each legend row names the status and gives its count.
  4. Title beside the ring: "31 of 50 tasks done", and "In 3 projects in Now" under it. The numbers add up on screen.
  5. For screen readers: role="img" with the label "Now: 62% done. 31 done, 9 in progress, 3 blocked, 7 to do." The legend is real text as well.
  6. Statuses with no tasks stay in the legend as a muted "0", so the list never changes shape.
  7. Not tappable. Filtering by segment is out of scope.

Empty states

  • No projects in Now: today's empty card, unchanged: Nothing in the "now" lane. Add a project.
  • Projects in Now but no tasks: no donut. The project cards show as today, each with "No tasks yet". An empty ring would say nothing.
  • Everything done: a full green ring, "100% done", with the other three at 0.

SVG sketch: <circle r="50" stroke-width="14" stroke="var(--done)" stroke-dasharray="len gap"> per status, rotated −90°. One status at 100% draws a single full circle with no gap.

8. Left open by the brief

  1. There is no project page. The task asked for one. The brief puts the action in the edit sheet. This mockup keeps it that way: the done card is the closed project's view.
  2. Reopen sends no notice. The brief covers only the close. Maya will see their tasks come back with no word of why. Worth adding a "Ana reopened Website" notice later.
  3. The donut can drop when you close. Closing Website takes its 8 done tasks out of the count: 62% becomes 61%. That is right for "current work", but someone may expect it to go up.
  4. The count can change while the confirm is open. The confirm says "4 open tasks". If someone finishes one before Ana taps, the server closes 3. Suggest the toast reports the real number. It does already, "3 tasks closed", so no extra screen.
  5. The free-text status stays "Active" after a close. It is hidden on done cards and comes back on reopen. Should a close clear it? I would leave it alone.
  6. Show all reloads the lane with every done project. With hundreds, one long list. Fine for a team of four for years.
