1. Desktop board: drag to a spot

Ana drags "Order tins" to the top of To do in Website. An amber line shows where it lands. The card stays faded in its old place until the drop. Nothing else on the board changes.

Desktop · 1440 · Ana, dragging within To do
Into another column, between two cards

Decisions

  1. The line sits in the gap between cards, with a ring at its start. That is the usual "it goes here" sign.
  2. Amber, the app's one accent. Today's blue drop outline becomes amber too, because blue means "in progress".
  3. No column outline while the line shows. The line is the only signal, so it never says two things at once.
  4. Over a card, the line goes above or below it by which half the pointer is in.
  5. No toast after a drop. If the save fails: error toast "Couldn't move Order tins. The board is back as it was." and the column refreshes.

3. Reorder mode: tasks

Phones have no board, only the list grouped by status. "Reorder" sits at the end of the filter row. Tapping it swaps the filters for an amber bar with "Done", and gives each row up and down arrows. Rows stop opening while it is on.

Phone · before · All
Phone · reordering · "Order tins" just moved up
Phone · the save failed

How it behaves

  1. The top row in each group has no up arrow; the last has no down arrow. A group of one has neither. The gap stays, so arrows line up.
  2. Arrows move a task within its status group only. Moving to another status is still done in the task sheet.
  3. The moved row tints amber for a moment and stays on screen. A screen reader hears "Order tins, 2 of 7 in To do".
  4. Each tap saves straight away, with no spinner: the move shows at once. If it fails, the toast says so and the list goes back.
  5. Tapping Done, leaving the page, or changing filter ends reorder mode. There is nothing to save at the end.
  6. The Done filter has no Reorder button. Done stays newest first.
  7. With "Mine" or a search on, arrows move past the visible rows only. Hidden tasks keep their place.

4. Reorder mode: roadmap

Leo opens Next and taps Reorder. While reordering, cards fold to one line (colour, name, status) so a whole lane fits on the screen and the arrows have room. He taps up on "Spring blend" and it moves above "Gift box redesign". Done brings back the full cards.

Phone · before · Next
Phone · reordering · Spring blend moved up

Decisions

  1. Reorder goes next to the lane hint, not the top bar. The top bar already holds the title, "Project" and the bell.
  2. Folded cards, because full cards are about 170px tall: only three fit on screen, and a move can push the card out of view.
  3. The lane switcher stays, so Leo can reorder Now next without leaving the mode.
  4. On desktop the four columns get the same folded cards with 32px arrows.
  5. Home's "Roadmap: now" and the task form's project list follow this order. They don't change in looks.

5. Done columns can't be reordered

Done keeps newest first, and says so in its header. No line appears between done cards, and no arrows in reorder mode. A task can still be dropped on Done: the whole column lights up and the card lands at the top.

Phone · roadmap Done lane: no Reorder

Notes

  1. "Newest first" sits after the count in the board's Done header and in the roadmap's Done hint.
  2. Dropping a project on the roadmap's Done still opens the "Mark project done" confirm, as today. No outline there, since nothing lands until it is confirmed.
  3. The phone's Done lane shows "Newest first" where Reorder would be, so the missing button reads as on purpose.

6. Several owners

In the project form, "Owner" becomes "Owners": the same tap-to-add people pills as a task's assignees, on their own row. Raj ticks Ana and Leo and saves. Each gets "Raj made you owner of Website". There is no separate project page today, so owners show on the card and in this form.

Decisions

  1. Owners moves out of the Lane / Status / Owner row onto its own row, as Assignees does in the task form. Pills don't fit in a third of the row.
  2. No owners is allowed and shows no avatars, as an unowned project does today.
  3. Owners move from the title row to the end of the pill row. In four desktop columns, three avatars beside the name cut "Wholesale catalogue" to "Whole…". Up to three 28px avatars, then a "+1" circle the same size. The stack's label reads "Owners: Tom, Ana, Leo and Maya".
  4. The form's lead line changes from "with one owner" to "A workstream on the roadmap. Owners can mark it done."
  5. Done cards show the same stack.

8. Do the arrows fit on a 390px task row?

Yes, if the row drops its avatars and note count while reordering, and the title may wrap to two lines.

PartWidth
Screen less page padding (16 + 16)358
Row padding (14 left, 8 right)-22
Status icon + gap-30
Two 44px arrows + 4px between + 10px gap-102
Left for title and project line204px, about 26 characters a line

With avatars kept (three at 28px, about 70px) the title would get about 130px: too tight. Stacking the two arrows in one 44px column would make each 22px tall: below the 44px rule. So: hide the extras, wrap the title to two lines, keep full-size arrows. On the desktop board (cards about 265px) 32px arrows leave the title about 170px, also wrapping.
