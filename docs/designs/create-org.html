1. Where "New organisation" lives

Priya owns Acme Studio. It is her only organisation. She wants a separate space for Lumen Café, the café she is opening with a friend. In PR 3 her org name was plain text, because she had nothing to switch to. In PR 4 the switcher shows for everyone, so the new row is always one click or tap away.

Desktop · 1440 · one org, menu open, keyboard focus on New organisation

Decisions

  1. The menu ends with a hairline and one row: a dashed square with a plus, then "New organisation". It is the last row, after any pending requests, exactly where section 7 of the PR 3 mockup left room for it.
  2. The row sits outside the scrolling list. With nine orgs the list scrolls and "New organisation" stays in view at the bottom.
  3. The dashed square tells it apart from a real org at a glance. A real org has a filled amber initial.
  4. It is a menuitem, not a menuitemradio. It opens the form, it does not switch. Arrow keys reach it like any row. Typing N reaches it too.
  5. Without JavaScript it is a link to /orgs/new, a plain page with the same form.
  6. Owner, admin and member all see it. An organisation belongs to the person who creates it, so the role in the current org does not matter.

The switcher for one org

Recommended: the chevron shows for everyone now. PR 3's rule ("plain name with one org") becomes "always a button", except while a super admin is acting with no membership of their own.

  • One control that always works the same, in the same place.
  • A menu with your one org and "New organisation" is small but honest. It shows the idea that you can have more than one.
  • The cost: a chevron on every one-org sidebar, for a feature most people will never use. It is quiet (muted, 16px), so this is small.

The alternative is a plain name plus a "New organisation" row on More only. Desktop would then have no entry at all, since More is a phone page. So it is not really an option on desktop.

Build note: org_menu becomes true for every active member. While acting, it stays as PR 3 has it: true only with a membership of your own.

2. The form

Two fields. Signup asks for an organisation name, a username, an email and a password (assets/views/signup/new.html). Priya already has an account, so only the first two are left. Signup does not ask for a time zone, so this form does not either.

Desktop · 1440 · the dialog over Home, filled in

Desktop: a dialog, not a page

  1. The app's dialog.sheet already turns into a centred 560px dialog at 768px and up. This uses it as it is. No new component.
  2. A dialog keeps Priya where she was. Cancel puts her back in Acme Studio with nothing changed.
  3. Two fields do not need a page. A page would also need its own place in the sidebar, which it does not have.
  4. /orgs/new stays as a plain page for no JavaScript, and for a link someone types. Same form, inside the app shell.
  5. Focus starts in "Organisation name". Esc and Cancel close it and put focus back on the switcher button.

3. After creating

Priya is the owner of Lumen Café, the browser switches into it, and she lands on Home there. A toast says it is ready. The Getting started guide is waiting, because it belongs to the membership and this membership is new.

Desktop · 1440 · Home in Lumen Café, first run

Decisions

  1. Toast: "Lumen Café is ready. You're the owner." The normal dark toast, bottom right on desktop and above the tab bar on phones, gone after 3.5 seconds.
  2. The same trick as a switch: the create redirects to /dashboard?created=1, Home words the toast from the org it really resolved, and app.ts drops ?created=1 so a reload does not repeat it.
  3. The Getting started guide shows at 0 of 5, the owner's steps: invite your team, a project, a task, hello in #general, tag a teammate. "Invite your team" is first and amber, because a new org with nobody in it is the real next step.
  4. Every count is 0 and the empty states are today's: "Nothing in the "now" lane. Add a project" and "Nothing on your plate. Add a task".
  5. #general and the starter document folders exist already. create_with_owner makes them, the same as at signup.
  6. The sidebar button reads "Lumen Café". The menu now lists both orgs, A to Z.
Question for Raj: the welcome pop-upSkip it for someone who already belongs to another org (recommended). welcomed_at is per membership, so today Priya would get the four-slide tour of an app she already uses, on top of the toast. The fix: set welcomed_at when the membership is made by "New organisation". The guide still shows, since its steps are about this org.

4. Edge cases

A super admin acting inside someone else's org, a cap on how many orgs one person can make, and failures.

Phone · acting, form opened from a typed link
Phone · at the limit
Phone · no connection

Super admin acting

  1. Raj, acting in Acme Studio, sees no "New organisation" row in the menu or on More. That menu is about where he is acting and his way back. A create button there could read as "create inside Acme".
  2. If he opens /orgs/new by hand, the form works and says so first: "You're acting in Acme Studio. Creating this ends acting. The new organisation is yours, with you as owner."
  3. Creating clears the acting cookie, as a switch does, and lands him in his own new org. It is never created inside or on behalf of Acme.

A limit

Recommended: yes, 10 organisations created per account. Counted from organisations.created_by_id, so it can't be dodged by leaving. No real person needs more today. It stops a script, or a stuck button, from filling the database. At the limit the row still shows. The form says why instead of the fields, so nobody hunts for a missing button.

Failures

  • No connection: toast "Couldn't create the organisation. Check your connection and try again." The form stays open and filled.
  • Server error: a red alert at the top of the form: "Something went wrong, and nothing was created. Try again." Signup's transaction already makes it all or nothing.
  • Double submit: the button locks on the first press.
Question for Raj: the limit10 per account, with a plain message (recommended). Or no limit for now. If 10, is there a contact to name in the message? It says nothing about one in this draft.

6. Questions for Raj

Each with a recommendation.

  1. The switcher for one org: show the chevron and menu for everyone. Recommend: yes. Without it, desktop has no way in.
  2. Desktop form: a dialog (the existing .sheet, centred at 560px), with /orgs/new as the no-JavaScript page. Recommend: yes, over a full page.
  3. Username: ask for it, filled with your current one. Recommend: yes. It costs one glance, and per-org usernames are the point of memberships.
  4. Time zone: copy the current org's, no field. Recommend: yes, over the Europe/London default.
  5. Same name as one of your own orgs: refuse it. Recommend: yes. Names stay free across the platform.
  6. Welcome pop-up: skip it when you already belong to another org, keep the Getting started guide. Recommend: yes.
  7. Toast: "Lumen Café is ready. You're the owner." Recommend: yes.
  8. Super admin acting: no create row while acting; the form works from a typed link, says it ends acting, and makes the org the admin's own. Recommend: yes.
  9. Limit: 10 organisations created per account. Recommend: yes. Tell me if the message should name a contact.
  10. Stale tabs: the create runs as CurrentUser and is exempt from PR 3's org check. Recommend: yes. It writes into no existing org.
